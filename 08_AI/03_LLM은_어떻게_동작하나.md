# 03. LLM은 어떻게 동작하나 ⭐ 핵심

> 🎯 목표: **"LLM은 다음 토큰을 확률로 고르는 기계"** 라는 한 문장으로 할루시네이션, 토큰 비용, 컨텍스트 한계를 설명하고, RAG·도구 호출·에이전트의 구조를 그림으로 그릴 수 있다. 그리고 **LLM API도 결국 HTTP + JSON** 이라는 것을 확인한다.

---

## 도입

AI에게 "Spring Security 설정 코드 짜 줘"라고 했더니, **이미 없어진 클래스**를 자신 있게 써 줍니다.
버그일까요? 아닙니다. **LLM이 원래 그렇게 동작하기 때문**입니다. 원리를 알면 언제 의심해야 하는지 알 수 있습니다.

---

## 1. LLM의 본질 — 다음 토큰 맞히기

```
입력:  "대한민국의 수도는"
                         ↓  모델이 다음 토큰의 확률을 계산
         " 서울"  92%
         " 어디"   3%
         " 세종"   2%
         ...
                         ↓  하나를 고름 → " 서울"
입력:  "대한민국의 수도는 서울"
                         ↓  다시 다음 토큰 확률 계산 → "입니다" ...
```
> (위 확률 숫자는 설명을 위한 가상 값입니다.)

LLM은 이 과정을 **한 토큰씩 반복**해서 문장을 만듭니다. 여기서 세 가지 중요한 성질이 나옵니다.

| 성질 | 결과 | 개발자가 할 일 |
|---|---|---|
| **"그럴듯함"을 고른다, "사실"을 고르지 않는다** | 학습 데이터에 자주 나온 패턴이면 틀린 내용도 자신 있게 말함 → **할루시네이션** | 사실 확인이 필요한 답은 **공식 문서·실행·테스트로 검증** |
| **확률적으로 고른다** | 같은 질문에도 **매번 답이 조금씩 다름** | 서비스에 쓸 때는 출력 형식을 강제하고 **서버에서 검증** (05) |
| **학습 데이터 시점에 묶인다** | 컷오프 이후 바뀐 API·버전을 모름 | 버전을 **명시**하고, 최신 문서를 **직접 넣어 주기**(RAG) |

### 할루시네이션이 잘 일어나는 곳 — 개발 편

| 상황 | 예 |
|---|---|
| **버전이 바뀐 API** | Spring Security 6에서 제거된 `WebSecurityConfigurerAdapter`를 상속하는 옛날 코드 제안 |
| **존재하지 않는 것** | 없는 라이브러리, 없는 메서드, 없는 설정 키를 그럴듯한 이름으로 만들어 냄 |
| **드문 지식** | 사내 프레임워크, eGovFrame 세부 설정, 최근에 나온 버전 |
| **정확한 숫자·인용** | 논문 제목, 법 조항 번호, 통계 수치, URL |

> ⚠️ **존재하지 않는 패키지 이름은 보안 문제**이기도 합니다. AI가 자주 지어내는 가짜 패키지 이름을 공격자가 먼저 등록해 악성 코드를 심는 수법이 보고되었습니다. AI가 알려준 의존성은 **공식 저장소에서 실제로 있는지, 다운로드 수·관리 주체가 정상인지** 확인하고 추가하세요.

## 2. 토큰 — LLM의 글자 단위이자 요금 단위

LLM은 글을 글자 단위도, 단어 단위도 아닌 **토큰**이라는 조각으로 처리합니다.

```
"Hello, world!"        →  [Hello] [,] [ world] [!]
"안녕하세요 반갑습니다"  →  [안녕] [하세요] [ 반] [갑] [습니다]
```
> (토큰 분할 방식은 모델마다 다릅니다. 위는 개념 설명용 예시입니다.)

- **요금**: API는 대개 **입력 토큰 + 출력 토큰** 수로 과금합니다. 출력 토큰 단가가 입력보다 몇 배 비싼 경우가 많습니다.
- **한국어**: 모델과 토크나이저에 따라 다르지만, 같은 내용이라도 영어보다 **토큰이 더 많이 드는 경향**이 있습니다.
- **API 응답에 사용량이 찍혀 나옵니다** (4장의 `usage`). 비용 추적은 이 값으로 합니다.

### 비용 감 잡기 (가상 단가 계산)

> 단가는 모델마다, 시기마다 다릅니다. 아래는 **계산 연습용 가상 단가**입니다.
> 가정: 입력 100만 토큰당 $3, 출력 100만 토큰당 $15, 환율 1,400원

| 항목 | 계산 | 결과 |
|---|---|---|
| 요청 1건 (입력 2,000 + 출력 500 토큰) | 2,000×3/1,000,000 + 500×15/1,000,000 | $0.0135 ≈ **19원** |
| 하루 1만 건 | × 10,000 | $135 ≈ **19만 원/일** |
| 한 달 (30일) | × 30 | ≈ **570만 원/월** |

1건에 19원은 싸 보이지만, **사용자 수 × 호출 수**가 곱해지면 금방 커집니다. 그래서 05 문서의 **사용량 제한·캐싱**이 필요합니다.

## 3. 컨텍스트 윈도우 — AI의 작업 기억

컨텍스트 윈도우는 **한 번의 요청에 넣을 수 있는 토큰의 최대량**입니다 (입력과 출력 모두 포함되는 경우가 많음).

```
┌───────────────────────── 컨텍스트 윈도우 ─────────────────────────┐
│ [시스템 지시] [이전 대화 1] [답 1] [이전 대화 2] [답 2] ... [새 질문] │ → [새 답]
└────────────────────────────────────────────────────────────────────┘
```

**가장 중요한 사실: LLM API는 기억이 없습니다(stateless).**
챗봇이 앞의 대화를 "기억하는" 것처럼 보이는 이유는, **매 요청마다 이전 대화 전체를 다시 보내기 때문**입니다.

- 이것은 HTTP가 stateless인 것과 같은 구조입니다. [Security 모듈](../Spring/Security/04_세션_vs_JWT_비교.md)에서 로그인 상태를 세션·토큰으로 유지했듯, 대화 상태도 **클라이언트(우리 서버)가 관리**합니다.
- 대화가 길어질수록 **매 요청의 입력 토큰이 늘어나 비용이 커지고**, 한도를 넘으면 앞부분을 잘라 내거나 요약해야 합니다.
- 컨텍스트가 매우 길면 **중간에 있는 정보를 놓치는** 경향도 보고됩니다. 중요한 지시는 분명하게, 필요한 자료만 넣는 것이 좋습니다.

## 4. LLM API도 결국 HTTP + JSON

[07_Network 05 문서](../07_Network/05_HTTP는_TCP_위의_텍스트다.md)에서 HTTP가 "TCP 위의 텍스트"라는 것을 직접 확인했습니다. LLM API도 똑같습니다.

아래는 **Claude API**의 요청 예입니다. OpenAI, Gemini, 사내 로컬 LLM 서버도 이름과 필드는 조금씩 달라도 **"메시지 배열을 JSON으로 POST"** 하는 구조는 같습니다.

**요청 (Request)**
```http
POST /v1/messages HTTP/1.1
Host: api.anthropic.com
Content-Type: application/json
x-api-key: (API 키 — 절대 코드·깃에 넣지 말 것)
anthropic-version: 2026-10-21

{
  "model": "claude-opus-5-5",
  "max_tokens": 1024,
  "system": "너는 신입 개발자를 돕는 친절한 멘토다. 한국어로 짧게 답한다.",
  "messages": [
    {"role": "user", "content": "Connection refused와 Connect timed out의 차이를 한 줄로 알려줘"}
  ]
}
```

**응답 (Response)** — 주요 필드만
```json
{
  "id": "msg_...",
  "type": "message",
  "role": "assistant",
  "content": [
    {"type": "text", "text": "refused는 상대가 '그 포트엔 아무도 없다'고 거절한 것이고, timeout은 아예 대답이 없는 것입니다."}
  ],
  "stop_reason": "end_turn",
  "usage": {"input_tokens": 52, "output_tokens": 41}
}
```
> 모델 ID, `anthropic-version` 값, 응답 내용·토큰 수는 예시입니다. 실제 값은 [공식 문서](https://platform.claude.com/docs)에서 확인하세요. 실무에서는 HTTP를 직접 짜기보다 **공식 SDK나 Spring AI**를 씁니다 (05).

| 필드 | 의미 | 연결 개념 |
|---|---|---|
| `system` | 모델의 역할·규칙을 정하는 지시 | 프롬프트 설계 |
| `messages` | 대화 기록 배열. `user`와 `assistant`가 번갈아 옴 | **stateless — 매번 전체를 보냄** |
| `max_tokens` | 출력 토큰 상한. 넘으면 답이 잘림 | 비용 제어 |
| `stop_reason` | 왜 멈췄나. `end_turn`(정상), `max_tokens`(잘림) 등 | 잘린 답을 정상으로 착각하지 않기 |
| `usage` | 입력·출력 토큰 수 | **비용 계산** |

> 💡 **무작위성 조절**: 예전에는 `temperature` 같은 값으로 답의 무작위성을 조절했습니다. 최근 일부 모델·API 버전은 이 값을 **더 이상 받지 않기도** 합니다. "일관된 출력"이 필요하면 무작위성 조절보다 **출력 형식 지정(JSON 스키마)과 서버 검증**에 기대는 편이 안전합니다.

## 5. LLM의 한계를 보완하는 세 가지 방법

LLM 혼자서는 ① 최신·사내 정보를 모르고 ② 실제 행동(조회, 계산, 저장)을 못 합니다. 이를 보완하는 방법이 다음 세 가지입니다.

### ① RAG (검색 증강 생성) — "모르면 자료를 찾아서 같이 준다"

```
사용자 질문: "우리 회사 연차 규정에서 반차는 몇 시간이야?"
      │
      ▼
 ① 검색 ──▶ 사내 문서 DB에서 질문과 비슷한 문단 찾기 (임베딩 + 벡터 검색)
      │         → "반차는 4시간으로 한다 (취업규칙 제12조)"
      ▼
 ② 프롬프트 조립: [지시: 아래 자료로만 답하라] + [찾은 문단] + [질문]
      │
      ▼
 ③ LLM 호출 ──▶ "반차는 4시간입니다 (취업규칙 제12조)."
```

- **임베딩**: 글의 의미를 숫자 배열(벡터)로 바꾼 것. "연차"와 "휴가"처럼 **단어는 달라도 뜻이 비슷하면 벡터가 가깝습니다.** 그래서 키워드 검색으로 못 찾는 문서도 찾을 수 있습니다.
- **장점**: 모델을 다시 학습시키지 않고 최신·사내 정보를 반영. **근거(출처)를 함께 보여줄 수 있음.**
- **웹 개발자의 일**: 문서 수집·분할, 벡터 DB 저장, 검색 API, 프롬프트 조립 — 대부분 **익숙한 백엔드 작업**입니다.

### ② 파인튜닝 — "추가 학습으로 말투·형식을 바꾼다"

- 특정 형식이나 말투, 분야 용어에 익숙해지도록 모델을 추가 학습합니다.
- **최신 정보를 넣는 용도로는 RAG가 보통 더 적합합니다.** 파인튜닝은 비용과 관리 부담이 크고, 정보가 바뀌면 다시 학습해야 합니다.

### ③ 도구 호출(Tool use) → 에이전트 — "필요하면 우리 함수를 불러 달라고 한다"

```
우리 서버 ──▶ LLM: "질문: 서울 날씨 어때?"  + [사용 가능 도구: getWeather(city)]
LLM ──▶ 우리 서버: "getWeather(city='서울')를 호출해 줘"      ← LLM은 요청만 함
우리 서버: 실제로 날씨 API 호출 (External-API 모듈의 코드!) → "맑음, 18도"
우리 서버 ──▶ LLM: "도구 결과: 맑음, 18도"
LLM ──▶ 우리 서버: "서울은 맑고 18도입니다. 가벼운 겉옷을 챙기세요."
```

- **핵심: LLM은 함수를 직접 실행하지 않습니다.** "이 함수를 이 인자로 불러 달라"고 **요청**할 뿐, 실제 실행은 **우리 코드**가 합니다. 그래서 **권한 검사와 입력 검증은 우리 책임**입니다.
- 이 "요청 → 실행 → 결과 전달"을 **여러 번 반복하며 스스로 다음 행동을 고르면** 그것이 **에이전트**입니다.
- **MCP**는 이 도구들을 **표준 방식으로 공개**하는 규격입니다. 도구마다 연결 코드를 따로 짤 필요가 줄어듭니다.

| 방법 | 해결하는 문제 | 비용·난이도 | 웹 개발자 관여도 |
|---|---|---|---|
| 프롬프트 개선 | 지시가 모호함 | 낮음 | 높음 |
| **RAG** | 최신·사내 정보를 모름, 근거 필요 | 중간 | **높음 (백엔드 작업)** |
| **도구 호출 / 에이전트** | 실제 조회·행동이 필요 | 중간~높음 | **높음 (API·권한 설계)** |
| 파인튜닝 | 말투·형식·분야 특화 | 높음 | 낮음 (주로 ML 담당) |

> 🏢 **실무 원칙**: 위 표의 **위에서부터** 시도합니다. 프롬프트로 해결되면 RAG를, RAG로 해결되면 파인튜닝을 하지 않습니다.

## 🧪 실습 (20분)

1. **할루시네이션 관찰**: 사내 허용 챗봇에 아래처럼 물어보고, 답을 공식 문서와 대조하세요.
   > "Spring Security에서 WebSecurityConfigurerAdapter를 상속해서 로그인 설정하는 코드 보여줘"
   - 이 클래스는 Spring Security 6에서 **제거**되었습니다. AI가 경고 없이 이 코드를 주는지, 버전 문제를 알려주는지 확인하세요.
   - 그다음 "Spring Boot 4.1, Spring Security 7 기준으로"를 붙여 다시 물어보고 차이를 비교하세요. [Security 모듈](../Spring/Security/README.md)의 코드와도 비교해 보세요.
2. **stateless 확인**: 새 대화창에서 "내가 방금 뭐라고 했지?"라고 물어보세요. 왜 모르는지 3장으로 설명하세요.
3. **비용 계산**: 2장의 가상 단가로, "사용자 500명이 하루 20번씩 입력 3,000 / 출력 800 토큰을 쓰는 서비스"의 월 비용을 계산하세요.

<details>
<summary>3번 정답</summary>

- 1건: 3,000×3/1,000,000 + 800×15/1,000,000 = 0.009 + 0.012 = **$0.021**
- 하루: 500 × 20 = 10,000건 → **$210**
- 한 달(30일): **$6,300 ≈ 882만 원** (환율 1,400원)

</details>
