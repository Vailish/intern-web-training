# 00. Wireshark 설치와 사용법

> 🎯 목표: Wireshark를 설치하고, **내 PC 안에서 오가는 패킷을 잡아서(캡처) 원하는 것만 걸러 보는** 기본 사용법을 익힌다.

**Wireshark** 는 네트워크로 오가는 데이터(패킷)를 잡아서 보여 주는 무료 프로그램입니다.
네트워크는 눈에 보이지 않아서 어렵게 느껴집니다. Wireshark를 쓰면 **"3-way handshake"가 정말 3개의 패킷인지** 직접 확인할 수 있습니다.

---

## ⚠️ 시작 전에 — 보안 수칙 (반드시 읽기)

Wireshark는 강력한 도구라서 잘못 쓰면 문제가 됩니다.

1. **내 PC의 내 통신만 캡처합니다.** 다른 사람의 통신을 엿보는 것은 회사 보안 규정 위반이고, 경우에 따라 **법적 문제(통신비밀보호법 등)** 가 될 수 있습니다.
2. **회사 PC라면 설치 전에 사수·보안 담당자에게 확인합니다.** 회사마다 패킷 캡처 도구 사용 규정이 있습니다.
3. **캡처 파일(`.pcapng`)을 함부로 공유하지 않습니다.** HTTP(암호화 안 된) 통신의 비밀번호·쿠키, 사내 IP 구조가 그대로 담깁니다.
4. 이 모듈의 실습은 대부분 **루프백(내 PC 안에서만 오가는 통신)** 이라 안전합니다. 외부 통신은 03·05의 일부 실습뿐이고, 그때도 **필터로 대상을 좁혀서** 캡처합니다.

---

## 1. 설치 (Windows)

### 1-1. 내려받기
1. 공식 사이트 **https://www.wireshark.org/download.html** 접속
2. **Windows x64 Installer** 를 내려받습니다.
   > 비슷한 이름의 비공식 사이트가 많습니다. **반드시 `wireshark.org` 에서** 받으세요.

### 1-2. 설치 마법사
설치에는 **관리자 권한**이 필요합니다. 대부분 **기본값 그대로 Next** 를 누르면 됩니다. 확인할 화면은 두 곳입니다.

| 화면 | 할 일 |
|---|---|
| **Packet Capture** (Npcap 설치 여부) | ✅ **Install Npcap** 체크 유지. **Npcap이 없으면 캡처가 안 됩니다** (Wireshark는 화면, Npcap은 실제로 패킷을 잡는 드라이버) |
| **USB Capture** (USBPcap) | 필요 없음. 체크 해제해도 됨 |

### 1-3. Npcap 설치 마법사 (Wireshark 설치 중에 이어서 뜸)

| 옵션 | 권장 | 이유 |
|---|---|---|
| Restrict Npcap driver's access to Administrators only | **해제(기본값)** | 체크하면 캡처할 때마다 관리자 권한을 요구합니다 |
| Support raw 802.11 traffic (and monitor mode) | 해제(기본값) | 무선랜 저수준 분석용. 이 모듈에선 불필요 |
| Install Npcap in WinPcap API-compatible Mode | 기본값 유지 | 옛날 프로그램 호환용 |
| (있다면) Support loopback traffic / Legacy loopback | **불필요** | 현재 Npcap은 루프백 캡처가 **기본 기능**입니다. 이 옵션은 구버전 프로그램용 |

> 옵션 이름은 Npcap 버전에 따라 조금 다를 수 있습니다. **모르겠으면 기본값**이 정답입니다.

### 1-4. 설치 확인
Wireshark를 실행했을 때 첫 화면 인터페이스 목록에 **`Adapter for loopback traffic capture`** 가 보이면 성공입니다.

> **루프백(loopback)** = `127.0.0.1`, `localhost`. 패킷이 랜카드 밖으로 나가지 않고 **내 PC 안에서만** 도는 통신입니다.
> 이 모듈의 실습은 대부분 루프백에서 합니다. 내 PC 안에서 서버와 클라이언트를 모두 돌리기 때문입니다.

### macOS를 쓴다면
같은 사이트에서 macOS용(.dmg)을 설치합니다. 루프백 인터페이스 이름은 **`Loopback: lo0`** 입니다. 처음 실행할 때 권한 설정(ChmodBPF) 안내가 나오면 따릅니다.

## 2. 화면 구성 — 5개 영역만 알면 된다

```
┌──────────────────────────────────────────────────────────────┐
│ ① 툴바  [상어지느러미=시작] [빨간 네모=정지] [재시작]           │
├──────────────────────────────────────────────────────────────┤
│ ② 디스플레이 필터  [ tcp.port == 9000                   ] →  │
├──────────────────────────────────────────────────────────────┤
│ ③ 패킷 목록  No. | Time | Source | Destination | Protocol | Info │
│   1  0.000000  127.0.0.1  127.0.0.1  TCP  53437 → 9000 [SYN]  │
│   2  0.000106  127.0.0.1  127.0.0.1  TCP  9000 → 53437 [SYN, ACK] │
├──────────────────────────────────────────────────────────────┤
│ ④ 패킷 상세 (계층별로 펼쳐 보기)                                 │
│   ▶ Null/Loopback                                             │
│   ▶ Internet Protocol Version 4, Src: 127.0.0.1 ...           │
│   ▶ Transmission Control Protocol, Src Port: 53437 ...        │
├──────────────────────────────────────────────────────────────┤
│ ⑤ 바이트 (실제 0과 1을 16진수로)  0000  02 00 00 00 45 00 ...  │
└──────────────────────────────────────────────────────────────┘
```

| 영역 | 보는 법 |
|---|---|
| ③ 패킷 목록 | 한 줄 = 패킷 하나. 가장 중요한 칸은 **Info** (무슨 패킷인지 요약) |
| ④ 패킷 상세 | 한 패킷을 **계층별로** 펼쳐 봄 → [01 문서](./01_큰그림_계층과_주소.md)의 "봉투" 구조가 그대로 보임 |
| ⑤ 바이트 | ④에서 항목을 클릭하면 해당 바이트가 강조됨 |

## 3. 기본 사용 순서

1. **인터페이스 고르기**: 첫 화면에서 `Adapter for loopback traffic capture` 를 **더블클릭** → 바로 캡처 시작
2. **실습 실행**: 예를 들어 socket-lab 서버와 클라이언트로 메시지 주고받기
3. **정지**: 툴바의 **빨간 네모** (안 멈추면 계속 쌓여 화면이 복잡해짐)
4. **필터 입력**: ② 칸에 `tcp.port == 9000` 입력 후 Enter → 관련 패킷만 남음
5. **분석**: 패킷 클릭 → ④에서 계층별로 펼쳐 보기
6. (선택) **저장**: File → Save As → `.pcapng` (공유 주의!)

> 💡 **빈 화면이면?** 정지 상태인지, 필터가 너무 좁은지, 인터페이스를 잘못 골랐는지(이더넷 vs 루프백) 확인하세요. `localhost` 끼리 통신은 **이더넷이 아니라 루프백**에서만 보입니다.

## 4. 필터 — 두 종류를 헷갈리지 말 것

| | **캡처 필터** | **디스플레이 필터** (주로 이걸 씀) |
|---|---|---|
| 언제 적용 | 캡처 **시작 전**, 조건에 맞는 것만 저장 | 캡처 **후**, 화면에 보일 것만 고름 |
| 입력 위치 | 첫 화면 인터페이스 목록 위 칸 | 캡처 화면 위 초록/빨간 칸 |
| 문법 예 | `tcp port 9000` | `tcp.port == 9000` |
| 틀렸을 때 | 시작 자체가 안 됨 | 칸이 **빨간색**으로 변함 |

### 이 모듈에서 쓸 디스플레이 필터

| 필터 | 의미 | 쓰는 문서 |
|---|---|---|
| `tcp.port == 9000` | TCP 9000번 포트 관련 (에코 서버) | 04 |
| `tcp.flags.syn == 1` | SYN 플래그가 있는 패킷 (연결 시작) | 04 |
| `tcp.flags.reset == 1` | RST 패킷 (연결 거부·강제 종료) | 04, 06 |
| `udp.port == 9001` | UDP 9001번 포트 (UDP 서버) | 04 |
| `icmp` | ICMP (ping, "포트 없음" 알림 등) | 04 |
| `tcp.port == 8080` | 스프링 앱 통신 | 05 |
| `http` | HTTP로 해석되는 패킷만 | 05 |
| `dns` | DNS 질의·응답 | 03 |
| `tls.handshake.type == 1` | TLS Client Hello (HTTPS 시작) | 05 |
| `ip.addr == 127.0.0.1` | 이 IP가 출발지 **또는** 목적지 | 공통 |

조건은 `&&`(그리고), `||`(또는)로 묶습니다. 예: `tcp.port == 9000 && tcp.flags.syn == 1`

## 5. 꼭 써 볼 기능 2가지

### 5-1. Follow TCP Stream — 대화 내용만 모아 보기
패킷 하나에 마우스 오른쪽 → **Follow → TCP Stream**.
흩어진 패킷의 데이터를 **대화처럼** 이어 붙여 보여 줍니다(빨강=클라이언트, 파랑=서버). HTTP 요청·응답을 볼 때 특히 좋습니다.

### 5-2. Flow Graph — 화살표로 흐름 보기
메뉴 **Statistics → Flow Graph** → 아래쪽 **Limit to display filter** 체크, Flow type은 **TCP Flows**.
SYN → SYN-ACK → ACK 가 **두 세로선 사이의 화살표**로 그려집니다. 3-way handshake를 그림으로 보기에 가장 좋습니다.

## 6. 처음 쓸 때 헷갈리는 것

| 질문 | 답 |
|---|---|
| `Seq=0` 인데, 순서 번호가 진짜 0부터 시작하나요? | 아닙니다. 실제로는 무작위 큰 숫자로 시작합니다. Wireshark가 보기 쉽게 **상대값**(relative)으로 바꿔 보여 주는 것입니다 |
| 줄 색깔이 무슨 뜻이에요? | Wireshark의 기본 색 규칙입니다. 빨강·검정 배경은 RST나 문제 가능성이 있는 패킷을 강조한 것 |
| 같은 패킷이 두 번 보여요 | 여러 인터페이스를 동시에 캡처하면 그럴 수 있습니다. 하나만 고르세요 |
| HTTPS 내용이 안 보여요 | 정상입니다. **암호화되어 있기 때문**입니다 (05 문서) |
| 명령줄로도 쓸 수 있나요? | `tshark` 가 함께 설치됩니다. 예: `& "C:\Program Files\Wireshark\tshark.exe" -i "\Device\NPF_Loopback" -f "tcp port 9000"` |

## 체크리스트

- [ ] Wireshark 첫 화면에 `Adapter for loopback traffic capture` 가 보인다
- [ ] 캡처 시작 → 정지 → 디스플레이 필터 적용을 할 수 있다
- [ ] 캡처 필터와 디스플레이 필터의 차이를 안다
- [ ] Follow TCP Stream, Flow Graph를 열 수 있다
- [ ] 캡처 파일을 함부로 공유하면 안 되는 이유를 설명할 수 있다
