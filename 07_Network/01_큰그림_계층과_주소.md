# 01. 큰 그림 — 계층과 주소

> 🎯 목표: 데이터가 **여러 겹의 "봉투"(계층)** 에 담겨 전달된다는 것과, **봉투마다 다른 주소**(MAC, IP, 포트)가 적힌다는 것을 이해한다.
> 그리고 Wireshark로 **실제 패킷 한 개를 열어서** 그 봉투들을 직접 확인한다.

---

## 도입 — "브라우저와 서버 사이에 뭐가 있지?"

`http://localhost:8080` 을 입력하면 화면이 뜹니다. 그 사이에 여러 일이 나눠서 처리됩니다.

- **누구에게?** → 어느 **컴퓨터**인지 (IP 주소)
- **그 컴퓨터의 어느 프로그램에게?** → 스프링 앱인지 MySQL인지 (포트 번호)
- **어떤 말로?** → HTTP라는 약속된 형식
- **빠짐없이, 순서대로?** → TCP가 책임짐
- **바로 옆 장비까지 어떻게?** → 랜선·와이파이 (MAC 주소)

이 일을 한 프로그램이 다 하지 않고, **층(계층)마다 하나씩 나눠** 맡습니다. 이것이 **계층 구조**입니다.

---

## 1. TCP/IP 4계층

| 계층 | 하는 일 | 대표 프로토콜 | 이 계층의 "주소" | 예시 |
|---|---|---|---|---|
| **4. 응용 (Application)** | 프로그램끼리 **무슨 말을** 할지 | HTTP, HTTPS, DNS, SSH | URL, 도메인 이름 | `http://localhost:8080/intro/new` |
| **3. 전송 (Transport)** | **어느 프로그램에게**, **믿을 수 있게** 전달할지 | **TCP**, **UDP** | **포트 번호** | `8080`, `3306` |
| **2. 인터넷 (Internet)** | **어느 컴퓨터에게**, 어떤 길로 갈지 | **IP**, ICMP | **IP 주소** | `127.0.0.1`, `192.168.0.10` |
| **1. 네트워크 접근 (Link)** | **바로 옆 장비까지** 실제로 전송 | 이더넷, Wi-Fi | **MAC 주소** | `A4-5E-60-xx-xx-xx` |

### 택배로 비유하면

```
[ 상품 ]                                   ← 응용: HTTP 요청 "GET /intro/new ..."
[ 수령인: 8080호(스프링 앱) | 상품 ]         ← 전송: TCP 헤더 (포트 번호)
[ 주소: 서울시 OO구 127.0.0.1 | 8080호 | 상품 ]   ← 인터넷: IP 헤더 (IP 주소)
[ 다음 물류센터 | 주소 | 8080호 | 상품 ]      ← 링크: 이더넷 헤더 (MAC 주소)
```

- 보낼 때는 **위에서 아래로** 봉투를 한 겹씩 씌웁니다 → **캡슐화(encapsulation)**
- 받을 때는 **아래에서 위로** 한 겹씩 벗깁니다
- 각 계층은 **자기 봉투만** 읽습니다. IP는 안에 HTTP가 들었는지 신경 쓰지 않습니다. 그래서 계층을 따로따로 바꿀 수 있습니다(예: Wi-Fi → 유선으로 바꿔도 HTTP 코드는 그대로).

> 💡 **MAC과 IP의 차이:** MAC은 **바로 다음 장비까지**(공유기까지)의 주소라 구간마다 바뀝니다. IP는 **최종 목적지** 주소라 끝까지 유지됩니다(공유기 NAT는 예외 → 02 문서).
> 택배 송장의 최종 주소(IP)는 그대로인데, "다음 물류센터"(MAC)는 거칠 때마다 바뀌는 것과 같습니다.

## 2. OSI 7계층은?

학교·면접에서는 **OSI 7계층**을 자주 묻습니다. 실제 인터넷은 TCP/IP 4계층으로 동작하므로, **대응 관계만** 알면 충분합니다.

| OSI 7계층 | TCP/IP 4계층 | 한 줄 요약 |
|---|---|---|
| 7 응용 / 6 표현 / 5 세션 | **응용** | 프로그램이 주고받는 내용 (HTTP 등) |
| 4 전송 | **전송** | TCP / UDP, 포트 |
| 3 네트워크 | **인터넷** | IP, 라우터 |
| 2 데이터링크 / 1 물리 | **네트워크 접근** | MAC, 스위치, 케이블·전파 |

> 면접 팁: "L4 로드밸런서", "L7 로드밸런서"의 L4·L7이 바로 OSI 계층 번호입니다. L4는 **IP·포트**까지만 보고 나누고, L7은 **HTTP 내용(URL 등)** 까지 보고 나눕니다.

## 3. 실습 — 내 PC의 주소 확인하기

```powershell
ipconfig /all
```

현재 연결된 어댑터(예: `이더넷 어댑터 이더넷`, `무선 LAN 어댑터 Wi-Fi`)에서 다음을 찾으세요.

| 항목 | 계층 | 의미 |
|---|---|---|
| 물리적 주소 (Physical Address) | 링크 | **MAC 주소**. 랜카드에 정해진 번호 |
| IPv4 주소 | 인터넷 | 이 네트워크 안에서 내 PC의 **IP** |
| 서브넷 마스크 | 인터넷 | 같은 네트워크의 범위 (02 문서) |
| 기본 게이트웨이 | 인터넷 | 밖으로 나갈 때 거치는 **공유기·라우터** |
| DNS 서버 | 응용 | 이름 → IP 변환을 물어볼 곳 (03 문서) |

## 4. 실습 — 패킷 하나를 열어 봉투 확인하기 ⭐

### 4-1. 준비
1. Wireshark에서 **`Adapter for loopback traffic capture`** 캡처 시작 ([00 문서](./00_Wireshark_설치와_사용법.md))
2. PowerShell 창 두 개를 엽니다.

```powershell
# 창 1 — 서버
cd 07_Network\샘플\socket-lab
java "-Dfile.encoding=UTF-8" TcpEchoServer.java
```
```powershell
# 창 2 — 클라이언트
cd 07_Network\샘플\socket-lab
java "-Dfile.encoding=UTF-8" TcpClient.java
```

3. 창 2에 `hello` 를 입력하고 Enter → `[echo] hello` 가 돌아오면, Ctrl+Z 후 Enter로 종료
4. Wireshark 정지 → 필터 `tcp.port == 9000`

### 4-2. 데이터가 든 패킷 고르기
Info 칸에 **`[PSH, ACK] ... Len=7`** 인 줄을 클릭합니다. (`hello` 5글자 + 줄바꿈 `\r\n` 2바이트 = 7바이트)

### 4-3. 패킷 상세(④)를 펼쳐 보기

실제 캡처 결과 (포트 번호는 실행마다 다름):

```
Null/Loopback                                                       ← 링크 계층 (루프백이라 MAC 대신 간단한 헤더)
Internet Protocol Version 4, Src: 127.0.0.1, Dst: 127.0.0.1         ← 인터넷 계층: IP 주소
Transmission Control Protocol, Src Port: 53437, Dst Port: 9000, Len: 7   ← 전송 계층: 포트 번호
Data (7 bytes)                                                      ← 응용 계층: "hello\r\n"
```

**봉투 4겹이 그대로 보입니다.**

### 4-4. 바이트(⑤)로 보기 — 진짜 0과 1

```
0000  02 00 00 00 45 00 00 2f 05 03 40 00 80 06 f7 c3   ....E../..@.....
0010  7f 00 00 01 7f 00 00 01 d0 bd 23 28 2d 31 90 d5   ..........#(-1..
0020  a1 88 3a 2e 50 18 00 ff d5 41 00 00 68 65 6c 6c   ..:.P....A..hell
0030  6f 0d 0a                                          o..
```

| 바이트 | 봉투 | 해석 |
|---|---|---|
| `02 00 00 00` | 링크(루프백) | 루프백 헤더 (4바이트) |
| `45 00 00 2f ...` | **IP 헤더** (20바이트) | `45` = IPv4, `2f` = 전체 길이 47바이트, `06` = 안에 든 것이 **TCP** |
| `7f 00 00 01` × 2 | IP 헤더 안 | 출발지·목적지 IP = **127.0.0.1** (7f=127) |
| `d0 bd` / `23 28` | **TCP 헤더** (20바이트) | 출발지 포트 0xd0bd = **53437**, 목적지 포트 0x2328 = **9000** |
| `50 18` | TCP 헤더 안 | 플래그 `18` = **PSH + ACK** |
| `68 65 6c 6c 6f 0d 0a` | **데이터** | `h e l l o \r \n` |

④에서 `Internet Protocol Version 4` 줄을 클릭하면 ⑤에서 해당 20바이트가 **파랗게 강조**됩니다. 계층마다 눌러 보세요.

> 💡 **47바이트 = IP 헤더 20 + TCP 헤더 20 + 데이터 7.** 데이터 7바이트를 보내려고 헤더가 40바이트 붙었습니다. 작은 메시지를 아주 많이 보내면 비효율적인 이유입니다.

## 5. 실무 연결

- **로드밸런서 L4 / L7**: 위 2절. L7은 HTTP 봉투까지 열어 보고 URL별로 나눌 수 있습니다.
- **방화벽**: 대부분 **IP + 포트 + TCP/UDP** (인터넷·전송 계층)를 보고 허용·차단합니다. 그래서 방화벽 신청서에 이 세 가지를 적습니다.
- **"HTTPS인데 왜 IP·포트는 보여요?"**: 암호화는 **응용 계층 내용**에만 적용됩니다. IP·TCP 헤더는 길 찾기에 필요해서 암호화하지 않습니다(05 문서).

## 6. 헷갈리는 것

| 오해 | 실제 |
|---|---|
| "TCP/IP는 프로토콜 하나다" | TCP와 IP는 **서로 다른 계층의 다른 프로토콜**. 함께 쓰여서 묶어 부르는 것 |
| "MAC 주소로 인터넷 어디든 찾아갈 수 있다" | MAC은 **같은 네트워크 안**에서만 쓰임. 멀리는 IP로 찾아감 |
| "OSI 7계층대로 프로그램이 7개 있다" | OSI는 **설명용 참조 모델**. 실제 구현은 TCP/IP 4계층에 가까움 |
